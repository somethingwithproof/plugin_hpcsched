# Cacti core behavior

Research for [#22](https://github.com/somethingwithproof/plugin_hpcsched/issues/22), run 2026-11-15. Question: does each row of the plan's Cacti core facts table hold at `release/1.2.31` and on current `1.2.x`?

**Result.** Every function the plan names has the same signature at both refs, and every hook the plan uses has a core call site. Four plan statements needed correction. (1) `register_process_start()` records the calling process's pid, not the parent's, so it must be called inside the reader, and a holder past its timeout is killed with SIGTERM and replaced; with no `processes` table it returns true and gives no exclusion. (2) `exec_background()` takes one executable path and an argument array; the 1.2.x branch shell-quotes the path, 1.2.31 does not. (3) `INFO` capabilities: `poller_bottom` on a remote collector runs only for a plugin whose `INFO` has `remote_poller:1`; `remote_collect:1` is not needed unless the plugin hooks `poller_output`. The capability set is settled below. (4) A device template has no availability field, so availability None is set per device through `api_device_save()`. The facts that Maint's `is_device_in_maintenance` hook has no caller, that Thold loads Maint's functions file and then calls `plugin_maint_check_cacti_host()`, that data source names are `varchar(19)`, and that `poller_bottom` on a remote poller needs `remote_poller:1` were re-checked and hold; see [plugin_cloud's cacti-core.md](https://github.com/somethingwithproof/plugin_cloud/blob/main/docs/research/cacti-core.md), which this follows, and [maint-thold.md](maint-thold.md). Running a script server data query, a reindex, and a remote collector are *live*; the plugin_cloud run already executed a script server data query at 1.2.31 and its result is cited, not repeated.

## Plan corrections

1. Compatibility, background work bullet: add that `exec_background()` takes one executable path plus an argument array, that B quotes the path and R does not, that it gives no error when it cannot start, and that `register_process_start()` is called inside the reader (pid of the caller), kills a holder past its timeout, and is a no-op without the `processes` table.
2. Plugin metadata paragraph: replace "the final capability set is a milestone 1 item" with the settled line above.
3. Cacti objects, cluster device row: availability None is a per-device setting set by `api_device_save()` with `availability_method` 0; a device template has no such field.
4. Cacti objects, data queries row: say that removed indexes become orphans and are removed only if the query XML requests it, and that new indexes need a reindex.
5. Remote operation: plugin tables replicate only through the plugin's own `replicate_out`; `remote_agent` needs two or more enabled pollers; B authorizes by TCP peer address.
6. Compatibility, plugin lifecycle bullet: `api_plugin_register_hook()` and `api_plugin_register_realm()` must be called from a function whose name contains `install`, `upgrade`, or `setup`.

## Limits

- Read from source only. No Cacti, database, or poller was started in this session. The one executed result (a script server data query on an availability-None device at 1.2.31) is plugin_cloud's, not repeated.
- Spine behavior was not read.
- The `host_template.class` marker idea is untested.
